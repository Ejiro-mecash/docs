---

This endpoint allows you to process payouts in **Philippine Peso (PHP)** to recipients with a bank account in the Philippines. You can fund PHP payouts from a **USD** or **NGN** wallet.

---

## Endpoint

**POST:** `https://sandboxapi.me-cash.com/v2/payout`

---

## Supported Payment Channels

PHP payouts support the following payment channel:

| **Channel** | **Description** | **Use Case** |
| :---------- | :-------------- | :----------- |
| `BANK_TRANSFER` | Bank transfer to Philippine banks, routed using the bank's SWIFT code | Transfers to bank accounts in the Philippines |

---

## Before You Start: Create a Quote

Every payout needs a `quoteId`. Create a quote with `PHP` as the target currency and `PH` as the target country, using `USD` or `NGN` as the source:

```bash cURL
curl --location --request POST 'https://sandboxapi.me-cash.com/v1/quote' \
--header 'x-api-key: API_KEY_HERE' \
--header 'Content-Type: application/json' \
--data '{
  "paymentChannel": "BANK_TRANSFER",
  "source": {
    "amount": 100,
    "country": "US",
    "currency": "USD"
  },
  "target": {
    "country": "PH",
    "currency": "PHP"
  }
}'
```

<Note>
  PHP payouts follow the same limits as USD payouts. The quote response lists the limits that apply in its `rules` array, so check them before you create the payout. See [Create a Quote](/quote-docs/create-quote) for the full response.
</Note>

<Tab title="BANK_TRANSFER Fields">

| **Field** | **Type** | **Description** | **Required** |

---

## **Payout Transaction States**

The payout transaction can have one of the following states:

| **State** | **Description** |
|------------|-------------------------------------------|
| `COMPLETED` | The payout was successfully processed.   |
| `PENDING`   | The payout is still being processed.     |
| `FAILED`    | The payout failed to process.           |
| `REFUNDED`  | The payout has been sent back to sender. |

---

## Error Handling

| **Status Code** | **Meaning** | **Example Response** |
|:------------|:-----------------------|:------------------------------------------------|
| `400`       | Insufficient Balance   | Insufficient Balance                            |
| `401`       | Unauthorized           | Invalid API key provided.                       |
| `403`       | Forbidden              | IP not whitelisted                              |
| `404`       | Not Found              | The requested endpoint does not exist.          |
| `422`       | Unprocessable Entity   | Invalid quote ID provided.                      |
| `500`       | Internal Server Error  | An internal error occurred.                     |

## **Best Practices**
✅ Create a fresh quote right before the payout and use its `quoteId`.
✅ Confirm the recipient's **account number** and **SWIFT code** are correct.
✅ Make sure the recipient's name matches the name on their bank account.
✅ Use a valid API key in the headers.
✅ Handle error responses correctly in your integration.

<Tip>
**Testing Failed Payouts:** In the sandbox environment, you can simulate a failed payout by setting `"remark": "fail"` in your request. This triggers a `payout.failed` webhook, allowing you to test your error handling.
</Tip>
